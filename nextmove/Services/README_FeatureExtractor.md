# FeatureExtractor

## Overview

The `FeatureExtractor` class derives performance metrics from object tracks generated by the `ObjectTracker`. It analyzes ball trajectories, player movement, contact points, and identifies performance issues to provide actionable coaching insights.

**Validates:** Requirements 4.1-4.7, 5.1-5.8, 6.1-6.7, 7.1-7.6

## Usage

```swift
let featureExtractor = FeatureExtractor()

// Extract features from tracks
let features = try await featureExtractor.extractFeatures(
    from: tracks,
    sportType: .pickleball
)

// Access ball trajectories
for trajectory in features.ballTrajectories {
    print("Direction: \(trajectory.direction)")
    print("Depth: \(trajectory.depth)")
    print("Speed: \(trajectory.estimatedSpeed ?? 0) units/sec")
    print("Confidence: \(trajectory.confidence)")
}

// Access rallies
for rally in features.rallies {
    print("Rally duration: \(rally.duration) seconds")
    print("Shot count: \(rally.shotCount)")
}
```

## Ball Trajectory Analysis

### Shot Direction Classification

The system classifies shot direction based on horizontal movement relative to vertical movement:

- **Cross-Court**: Significant horizontal movement to the right (horizontalRatio > 0.3, positive delta)
- **Down-the-Line**: Significant horizontal movement to the left (horizontalRatio > 0.3, negative delta)
- **Middle**: Mostly vertical movement (horizontalRatio < 0.3)

### Shot Depth Estimation

Shot depth is determined by the endpoint's y-coordinate in normalized court space (0.0 = baseline, 1.0 = net):

- **Kitchen**: y >= 0.7 (near net, non-volley zone)
- **Mid-Court**: 0.3 <= y < 0.7 (middle third of court)
- **Baseline**: y < 0.3 (near baseline)

### Ball Speed Calculation

Ball speed is computed by:
1. Calculating distance between consecutive detections (Euclidean distance in normalized coordinates)
2. Dividing by time delta between detections
3. Averaging speeds across all detection pairs in the track

Returns `nil` if insufficient data (< 2 detections).

### Rally Computation

Rallies are identified by grouping ball trajectories with temporal proximity:
- Trajectories within 3 seconds are grouped into the same rally
- Gaps > 3 seconds indicate rally boundaries
- Each rally includes:
  - Start/end timestamps
  - Shot count (number of ball trajectories)
  - Duration (computed from timestamps)
  - Outcome (currently `.unknown`, to be enhanced with contact analysis)

## Confidence Scoring

### Trajectory Confidence
- Inherited from the underlying track's average confidence
- Trajectories with confidence < 0.5 are marked as low-confidence (Requirement 4.6)
- Low-confidence trajectories are still included but flagged for UI indication

### Overall Confidence
- Computed as the average of all ball trajectory confidences
- Used to indicate overall reliability of the feature extraction
- Will be enhanced to include player movement and contact point confidences in future tasks

## Error Handling

The `FeatureExtractor` throws `FeatureExtractionError` in the following cases:

- **insufficientData**: No ball tracks found in the input
- **invalidTrackData**: Track data is corrupted or invalid (future enhancement)

## Notes

- All coordinates are normalized (0.0-1.0) for resolution independence
- Timestamps use CMTime for precise video timing
- The implementation is sport-agnostic at the trajectory level, with sport-specific rules applied via the `sportType` parameter
- Placeholder methods exist for player movement to maintain protocol compliance until Task 9.1
